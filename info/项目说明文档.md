# 东软颐养中心管理系统

## 一、项目概述

### 1.1 项目简介
本项目是一个基于 Java 控制台的**养老院信息管理系统（颐养中心管理系统）**，实现对养老院日常运营的全面数字化管理。

### 1.2 技术栈
| 项目 | 说明 |
|------|------|
| 开发语言 | Java 1.8 |
| 构建工具 | Maven |
| JSON 处理 | Jackson 2.13.5 |
| 数据存储 | JSON 文件（18个） |
| 运行环境 | 控制台（Console） |
| 设计模式 | 命令模式（Command Pattern） |

### 1.3 项目规模
| 层 | 类数 | 总方法数 |
|---|:---:|:---:|
| 实体层（pojo） | 15 | — |
| 数据访问层（dao） | 15 | ~85 |
| 业务逻辑层（service） | 16 | ~109 |
| 视图层（view） | 19 | ~120 |
| 工具层（utils） | 4 | ~25 |
| **合计** | **70** | **~340** |

## 二、系统架构

```
┌──────────────────────────────────────────────┐
│                   Main.java                    │
│               （程序入口 → 登录 → 角色分发）       │
└─────────────┬────────────────┬────────────────┘
              │                │
    ┌─────────▼──────┐  ┌─────▼──────────┐
    │ AdminMainView  │  │ StewardMainView│
    │   （管理员端8大功能）│  │  （管家端5大功能） │
    └───┬──┬──┬──┬───┘  └─┬──┬──┬──┬───┘
        │  │  │  │  （共13个子View，均实现MenuItem接口）
     ┌──┘  │  │  └──┐
     │     │  │     │
┌────▼─────▼──▼─────▼────┐
│      Service 层（16个）    │  业务逻辑 + 数据校验
└────────────┬───────────┘
┌────────────▼───────────┐
│       DAO 层（15个）      │  JSON 文件读写 + 唯一性校验
└────────────┬───────────┘
┌────────────▼───────────┐
│     data/  JSON文件（18个）│  持久化存储
└────────────────────────┘
```

### 2.1 分层职责
| 层 | 职责 | 实现细节 |
|---|------|---------|
| **pojo** | 数据模型 | 15个实体类，每个包含私有字段 + getter/setter + toString() |
| **dao** | 数据访问 | 使用 Jackson 读写 JSON 文件，每个 DAO 对应一个 JSON 文件；所有 add() 方法带唯一性校验 |
| **service** | 业务逻辑 | 封装 DAO 调用，增加数据校验、年龄计算、审核流程等业务规则；返回 boolean/null 明确成败 |
| **view** | 控制台交互 | 基于命令模式，每个功能模块独立成类，实现 MenuItem 接口的 execute() 方法 |
| **utils** | 工具支持 | 输入验证、JSON 序列化、ID 自增生成、排序比较器 |

## 三、功能模块详解

### 3.1 登录模块

**实现类：** `LoginView.java`

**功能描述：**
- 用户通过控制台输入用户名和密码登录系统
- 最多允许 **5 次尝试**，输入 `0` 可**主动退出**
- 登录成功后根据 `roleId`（1=管理员，2=健康管家）分发到不同主菜单

**实现逻辑：**
1. 调用 `UserService.login(username, password)` 验证凭证
2. `UserService` → `UserDao.login()` → 遍历 `user.json` 匹配已删除用户的用户名和密码
3. 返回匹配的 User 对象，设置当前登录用户

**预置账号（9个）**

| 账号 | 密码 | 角色 |
|------|------|------|
| admin | admin | 管理员 |
| admin1 | admin1 | 管理员 |
| admin2 | admin2 | 管理员 |
| admin3 | admin3 | 管理员 |
| steward1 | steward1 | 健康管家 |
| steward2 | steward2 | 健康管家 |
| steward3 | steward3 | 健康管家 |
| steward4 | steward4 | 健康管家 |
| steward5 | steward5 | 健康管家 |

### 3.2 管理员端功能（8大模块）

#### 3.2.1 客户管理

**实现类：** `CustomerManageView.java` + `CustomerService.java` + `CustomerDao.java`

| 功能 | 实现 |
|------|------|
| **客户列表（全部）** | 读取并排序显示所有未删除客户，按入住日期降序 |
| **客户列表（自理老人）** | 筛选 levelId==null 的客户 |
| **客户列表（护理老人）** | 筛选 levelId!=null 的客户 |
| **查找客户** | 按姓名**模糊匹配**（不区分大小写），支持搜索"刘"匹配刘大爷+刘奶奶 |
| **入住登记** | 输入姓名、身份证号(唯一)、选房间床位、填详情 → 自动计算年龄 → 写入 customer.json |
| **修改客户信息** | 按ID查询 → 显示当前值 → 直接回车保留原值 |
| **删除客户** | 逻辑删除（isDeleted=1），同时释放床位 |
| **分配健康管家** | 列出所有管家 → 选择ID分配或输入0取消 |
| **服务关注** | 查看客户已购护理项目 + 服务到期状态 |

**数据特征：** 14位客户，包含同姓（刘大爷/刘奶奶、张奶奶/张大爷）、同名（"小华"出现在多个客户家属中）场景。

#### 3.2.2 床位管理

**实现类：** `BedManageView.java` + `BedService.java` + `BedDao.java`

| 功能 | 实现 |
|------|------|
| **床位统计概览** | 遍历 bed.json → 统计总数/已占用/空闲/外出数 + 入住率 |
| **按楼层查看床位** | 按楼层分组显示每间房每个床位的状态 |
| **床位列表（全部）** | 按房间号+床位编号排序显示 |
| **床位调换** | 选择旧床位 → 选新床位 → 状态互换 → 同时更新关联客户 |
| **进入前可输入0退出** | 所有 ID 输入提示均带 `(0返回)` |

**床位状态：** 1=空闲 / 2=有人 / 3=外出

#### 3.2.3 护理管理

**实现类：** `NurseManageView.java` + `NurseService.java`

| 子模块 | 功能 |
|--------|------|
| **护理项目管理** | 增加/修改/删除/列表，按编号排序，名称唯一性校验 |
| **护理等级管理** | 4个等级（一级/二级/特级/康复），每个等级关联一组护理项目 |
| **客户护理设置** | 为客户选择护理等级 → 自动分配该等级对应的护理项目 |

#### 3.2.4 外出登记管理

**实现类：** `OutwardManageView.java` + `OutwardService.java`

| 功能 | 实现 |
|------|------|
| **外出申请列表** | 排序规则：待审核排最前 → 已通过 → 已拒绝；同状态按外出时间降序 |
| **审批外出申请** | 通过 → 标记审核状态；拒绝 → 标记拒绝原因 |
| **登记回院时间** | 仅已通过的外出记录可登记 |

#### 3.2.5 退住登记管理

**实现类：** `BackdownManageView.java` + `BackdownService.java`

| 功能 | 实现 |
|------|------|
| **退住申请列表** | 排序规则：待审核→已通过→已拒绝 |
| **审批退住申请** | 支持三种退住类型：正常退住(0)、死亡退住(1)、保留床位(2) |

#### 3.2.6 用户管理

**实现类：** `UserManageView.java` + `UserService.java` + `UserDao.java`

| 功能 | 实现 |
|------|------|
| **用户列表** | 按角色排序（管理员在前），同角色按用户名升序 |
| **添加用户** | 用户名唯一性校验，重复添加时提示错误并拒绝 |
| **修改用户** | 密码可选择修改或保留 |
| **删除用户** | 逻辑删除 |

#### 3.2.7 膳食菜品管理

**实现类：** `FoodManageView.java` + `FoodService.java` + `FoodDao.java`

| 功能 | 实现 |
|------|------|
| 菜品库管理 | 25种预置菜品（主食/菜品/汤品/水果/饮品五类） |
| 增/删/改/查 | 名称唯一性校验 + 模糊搜索 |

#### 3.2.8 膳食日历编排

**实现类：** `MealCalendarView.java` + `MealService.java` + `MealDao.java`

| 功能 | 实现 |
|------|------|
| **一周菜单展示** | 遍历1-7天，每天显示三餐（早餐/午餐/晚餐）对应的菜品名称 |
| **某天菜单** | 单独查看指定星期几的菜单 |
| **添加膳食安排** | 选择周几+餐次+菜品 → 自动去重（同天同餐次同菜品拒绝添加） |
| **删除膳食安排** | 按天展示→选择记录ID→确认删除 |

**预置数据：** 78条膳食记录，覆盖周一至周日每天三餐。

## 四、技术亮点

### 4.1 命令模式（Command Pattern）

所有子 View 均实现 `MenuItem` 接口的 `execute()` 方法，主菜单通过统一的模式分发调用：

```java
// 接口定义
public interface MenuItem { void execute(); }

// 管理员菜单分发
case 1: new CustomerManageView().execute(); break;
case 2: new BedManageView().execute(); break;
```

**优点：** 新增功能只需新建 View 类实现 MenuItem，主菜单加一行 case，完全解耦。

### 4.2 JSON 文件持久化

使用 Jackson 库实现 Java 对象与 JSON 文件的双向转换：

| 工具类 | 功能 |
|--------|------|
| `JsonUtil.readList(file, class)` | JSON → `List<T>` |
| `JsonUtil.writeList(file, list)` | `List<T>` → JSON |
| `IdGenerator.nextId(file)` | 读取文件中最大 ID +1 返回 |

**优点：** 无需数据库，数据即 JSON 文件，方便查看和调试。

### 4.3 统一排序体系

所有查询结果均经过排序再展示，集中管理在 `SortUtil.java`：

| 实体 | 排序规则 |
|------|---------|
| 用户 | 管理员在前 → 同角色按用户名升序 |
| 客户 | 按入住日期降序（最新在前） |
| 床位 | 按房间号 → 床位编号升序 |
| 护理内容 | 按编号升序 |
| 护理等级 | 按等级名称升序 |
| 护理记录 | 按护理时间降序 |
| 外出/退住 | 待审核排最前 → 同状态按时间降序 |
| 菜品 | 按名称升序 |
| 膳食安排 | 按餐次排序 |

### 4.4 数据的唯一性校验

| 实体 | 唯一键 | 校验位置 |
|------|--------|---------|
| 用户 | username | UserDao.add() |
| 客户 | idcard（身份证号） | CustomerDao.add() |
| 护理内容 | nursingName | NurseContentDao.add() |
| 护理等级 | levelName | NurseLevelDao.add() |
| 菜品 | foodName | FoodDao.add() |
| 膳食安排 | weekDay+mealType+foodId | MealDao.add() |

### 4.5 输入健壮性

- 所有输入通过 `InputUtil` 处理，统一使用 `Scanner.nextLine()` 避免缓冲区问题
- 整数输入循环等待直到合法，防止 `InputMismatchException`
- 所有 ID 输入均提供 `(0返回)` 取消机制，共 24 处
- 删除/修改操作前均有二次确认

### 4.6 逻辑删除

所有删除操作均为逻辑删除（`isDeleted = 1`），数据不丢失可恢复。

## 五、数据模型 ER 关系

```
User（用户）──┐
              ├── 1:N ── Customer（客户）
              │              ├── 1:1 ── Preference（饮食偏好）
              │              ├── 1:1 ── Bed（床位）
              │              ├── 1:N ── NurseRecord（护理记录）
              │              ├── 1:N ── CustomerNurseItem（已购护理项目）
              │              ├── 1:N ── Outward（外出记录）
              │              ├── 1:N ── Backdown（退住记录）
              │              └── 1:N ── BedDetail（床位使用历史）
              │
NurseLevel（护理等级）── 1:N ── NurseLevelItem ── N:1 ── NurseContent（护理内容）
                                              │
CustomerNurseItem（客户护理项目）── N:1 ── NurseContent
                                              │
Meal（膳食安排）── N:1 ── Food（菜品）
```

## 八、设计模式与扩展性

| 设计模式 | 应用场景 | 效果 |
|---------|---------|------|
| **命令模式** | View 层所有子功能 | 新增功能只需新建类实现 MenuItem，完全不改动已有代码 |
| **分层架构** | pojo→dao→service→view | 各层职责单一，修改某层不影响其他层 |
| **Comparator 集中管理** | SortUtil | 新增排序规则只需加一个常量，Service 层引用即可 |
| **接口抽象** | InputUtil 静态方法 | 全局复用，输入验证逻辑集中维护 |
